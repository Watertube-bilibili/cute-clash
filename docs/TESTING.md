# 测试与 Windows 7 验收

测试日期：2026-09-22。开发机为 Windows NT 10.0.26120（Windows 11），不是 Windows 7。

## 自动验证

0.3.0 使用 `scripts/build-windows.ps1 -RunTests` 编译正常发行的 x64 / x86 程序和自带运行时测试程序。两组测试使用对应位数的真实 Mihomo v1.19.31，各通过 **51 项断言 / 测试组**，结果位于 `artifacts/runtime-tests/<arch>/result.txt`。测试断言 CoreLib 从当前包目录加载，并报告 .NET 6.0.36，而非使用开发机安装的其他 .NET 版本。

新增检查覆盖旧版 Microsoft JSON 日期、恢复记录及设置双向兼容、嵌套 API 值、JSON 长度/深度限制、apphost 看门狗路径、clash:// 参数与签名字节、同一用户命名管道真实收发、长度/超时、慢连接恢复及请求去重。管道显式使用用户 SID，不依赖管理员令牌的 Owner 身份；跨用户写入没有开放。没有宣称已交互验证所有 UAC 提升等级组合。

开发者保留的 .NET Framework 工程另用 `scripts/build.ps1 -RunTests` 做回归检查，包含相同的订阅链接解析与管道检查。

覆盖 YAML 重复键、循环与复杂键、锚点展开资源限制、未知协议字段保留、配置覆盖和原子备份；使用假后端验证系统代理原状态保存、PAC/自动检测恢复、失败写入和不覆盖其他软件的修改。额外以只读方式调用真实 WinINet 获取设置，检查两种进程位数的本机结构体布局。

集成验证使用真实内核：配置导入、无效配置回滚、API 认证拒绝、策略组读取和节点选择、模式切换、本机 HTTP 转发、SOCKS5 协商和转发、流量统计、停止端口释放、异常退出后重启、订阅 URL 导入、有效订阅更新自动重连及无效更新不损坏原配置。还验证子进程不会继承可覆盖配置的 CLASH 环境变量。TUN 开启配置仅运行核心 `-t` 校验，没有在开发机启用 TUN。

八种协议示例均在 x64/x86 内核中通过 `-t`；示例没有真实服务器，未据此宣称完成协议握手测试。界面通过自身控件离屏绘制检查页面布局；这与 Windows 7 桌面实际使用验收不同。

中英文界面检查覆盖五个页面、订阅对话框、偏好保存和重新加载、最小窗口与设置滚动。0.3.0 增加两种语言的 clash:// 预填确认与取消检查，用本地 TCP 监听器验证确认前和取消后没有下载，配置及连接状态没有变化，标题不暴露 token。检查运行在 `--ui` 独立入口；不启用宿主系统代理或 TUN。仓库中的 `docs/images` 仅包含示例配置界面。

原生安装器已在 Windows 11 上实际执行 x64 / x86 安装、原地升级和卸载。逐项校验全部安装文件的 SHA256、内置运行时、快捷方式与协议命令；验证运行中应用和锁定核心会阻止覆盖，未标记的非空目录会被拒绝，卸载保留用户添加的文件及其他应用接管的协议关联。现有新旧数据目录字节未变，测试前的协议注册已完整还原。脚本为 `tests/InstallerSmoke.ps1 -Run`，本机记录在 `artifacts/installer-smoke`。这些安装检查不代表 Win7 实机验证。

已检查 PE 架构与最低系统版本：两种 GUI 分别为 x64 / x86；Mihomo 的 OS / Subsystem 版本均为 **6.1（Windows 7）**，Wintun DLL 为 6.0。此静态检查排除了意外打包较高系统基线二进制的情况，但不等同于验证所有运行时 API、驱动与网络行为。
